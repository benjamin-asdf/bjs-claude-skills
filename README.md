# bjs-claude-skills

Claude Code skills that are thinking operators: each one is a named move on a thinking object
(a bug, a plan, an assumption, a decision, a diff), with a fixed procedure and checkable output.

| Skill | Move | Status |
|---|---|---|
| `bug-layer-analysis` | one bug → mechanism class → broken assumption → process gap, each level searched and verified | used on real bugs |
| `pre-mortem` | assume a planned change failed, enumerate causes, generalize, make each cause checkable now | untested |
| `assumption-stress-test` | turn an assumption into cases that break it, run them, restate the assumption | untested |
| `decision-matrix` | status quo vs alternatives, facts in cells, judgment kept separate (Hickey) | used |
| `review-verify-loop` | reviewer proposes findings, one verifier per finding tries to refute it, repeat | used |
| `operator-neighborhood` | take one operator, span its axes, find free neighbors | untested |
| `operator-router` | choose which operator fits a problem before applying one | untested |

"Untested" means written, not yet run against real cases. Operators are conjectures; they stay
only if they find things a bare prompt would not.

## Install

Symlink a skill into the global skills directory:

```
ln -s "$PWD/skills/bug-layer-analysis" ~/.claude/skills/bug-layer-analysis
```

Output paths like `notes/<ticket>/…` are defaults; point them at your own notes directory in
your project's `CLAUDE.md`.
